Podpisový obřad (remote QSCD)

1PřípravaBridge sestaví PAdES podpisové pole a placeholder, spočítá SHA-256 z ByteRange.
2AutorizaceQTSP vytvoří signing session se SAD; uživatel dostane push do své aplikace (I.CA, Signer).
3PotvrzeníUživatel vidí dokument a hash, potvrdí PINem nebo biometrií. Klíč zůstává v QSCD.
4PodpisQTSP podepíše hash v certifikovaném HSM a vrátí raw signature + řetěz certifikátů.
5Embed + LTVBridge vloží CMS do PDF, přidá kvalifikované časové razítko a OCSP/CRL data.
6Validace + auditDSS ověří podpis, Bridge uloží report a dokončí submittera v DocuSealu přes API.

Tři varianty integrace s DocuSeal

A · nejrychlejší

Sidecar přes API

DocuSeal zůstane bez zásahu. Bridge převezme finální PDF, přidá QES a dokončí submittera přes PUT /api/submitters/:id. Pilot do několika týdnů, ale dva artefakty a dělený audit.

B · produkt

Fork s patchem

Nový typ pole qes a hook v dokončení submittera. Finální PDF DocuSealu už obsahuje QES, audit je jeden. Patch držet malý a izolovaný kvůli rebasování (AGPL + attribution).

C · dlouhodobě

Upstream SignatureProvider

Navrhnout DocuSealu rozhraní pro podpisové providery (CSC adaptér + lokální). Řeší i poptávku z diskuse #537 a je to stejná cesta, jakou plánuje Documenso.
